# Спецификация: Telegram-бот для учёта дедлайнов учебной группы

Актуально после переработки UX и архитектуры. Прежняя версия (тексты дедлайнов,
типы заданий с зашитыми напоминаниями, дублирующие slash-команды) не действует.

## Стек

Python 3.12, aiogram 3, SQLAlchemy 2 async + aiosqlite, alembic, APScheduler,
pydantic / pydantic-settings, uv, ruff, ty, pytest.

## Слои

```
domain      чистая логика: типы, правила напоминаний, календарь, форматирование чисел и дат
db          ORM-таблицы и репозитории; репозитории отдают доменные модели
services    менеджеры: ItemManager, GroupManager, ReminderService, DigestService
views       домен → текст (parse_mode=HTML)
ui          CallbackData-фабрики и клавиатуры
handlers    тонкие обработчики: собрать ввод → вызвать сервис → показать view
```

Правило: ORM не покидает `db/`, Telegram-типы не попадают в `services/` и ниже.

## Модель данных

### Item — задача или важная дата

| поле | тип | смысл |
|---|---|---|
| `id`, `group_id`, `subject_id` | int | `subject_id` — ON DELETE RESTRICT |
| `short_id` | int | человекочитаемый номер, уникален внутри группы |
| `kind` | `task` \| `event` | определяет поведение |
| `category` | str(16) | значение из набора, зависящего от `kind` |
| `title` | str(256) | |
| `description` | str(2048) \| None | |
| `links` | JSON list[str] | только http(s) |
| `due_at` | datetime \| None | UTC; None допустим только у `task` |
| `reminder_offsets` | JSON list[int] \| None | минуты до дедлайна; None — брать дефолт группы |
| `reminders_muted` | bool | напоминания по записи выключены |
| `created_by_user_id`, `created_at`, `is_active` | | удаление всегда мягкое |

Категории задач: `homework`, `lab`, `project`, `essay`, `other`.
Категории важных дат: `test`, `control`, `exam`, `defense`, `other`.

Различие типов:
- **task** — «сделать до». Дедлайн необязателен («до конца модуля»).
  В напоминании: «нужно сдать».
- **event** — «состоится в». Дата и время обязательны. В напоминании:
  «состоится». В списке — отдельная секция.

### Group

`name`, `invite_code` (уникален), `timezone` (IANA), `chat_id` (привязанный
чат), `digest_day` (0=пн … 6=вс), `digest_hour`, `digest_last_sent_at`,
`default_task_offsets` (по умолчанию `[1440]`), `default_event_offsets`
(по умолчанию `[10080, 4320, 1440]`), `reminder_hour` (по умолчанию 10).

### Прочее

`User` (с `active_group_id`), `GroupMember` (роль + `personal_reminders_enabled`),
`Subject` (уникален по имени внутри группы; сравнение имён регистронезависимое
и выполняется в Python, потому что SQLite `lower()` не знает кириллицы),
`ReminderLog` — ключ идемпотентности `(item_id, user_id, offset_minutes)`.

## Напоминания

Итоговый набор сроков считает `resolve_offsets`: запись заглушена → пусто;
у записи есть свой набор → он; иначе дефолт группы по `kind`.

`plan_reminders` переводит набор в моменты отправки:

- офсет кратен суткам → срабатывает в `reminder_hour` по времени группы
  за N дней до дедлайна;
- офсет меньше суток → ровно за указанный интервал;
- напоминание, попадающее на дедлайн или позже, отбрасывается.

Пресеты в интерфейсе: 2 недели, неделя, 3 дня, 2 дня, день, 3 часа, 2 часа,
час. Редактор — экран с тумблерами, без текстового ввода.

Рассылка (`ReminderService.send_batch`) идемпотентна: журнал коммитится сразу
после каждой успешной отправки, поэтому падение в середине батча не даёт
дублей при повторе. При изменении дедлайна, набора сроков или заглушения
журнал записи чистится, а расписание перестраивается.

После рестарта `bootstrap_from_db` восстанавливает будущие задания и догоняет
пропущенные, если до дедлайна осталось не меньше 30 минут.

## Дайджест

Раз в час общий тик проверяет все группы. Для каждой считается последний
наступивший слот `(digest_day, digest_hour)` в её поясе; если
`digest_last_sent_at` старше слота — дайджест отправляется. Слот фиксируется
даже когда отправлять нечего, чтобы не повторять попытку.

Горизонт — 14 дней. Группировка по локальным дням, отдельный блок «До конца
модуля». Отправка в `chat_id`, если он задан, иначе в личку участникам с
включёнными личными напоминаниями. Длинный дайджест режется по блокам и
строкам под лимит Telegram.

## Ввод дедлайна

Только кнопками. Инлайн-календарь: заголовок с месяцем и стрелками, шапка
дней недели, сетка месяца (прошедшие дни неактивны, сегодня в скобках),
быстрые кнопки «Сегодня / Завтра / +7 дней», для задач — «📌 До конца модуля».
Листать назад раньше текущего месяца нельзя, вперёд — не дальше двух лет.
Состояние календаря живёт в `callback_data`, не в FSM.

После даты — пресеты времени (у задач включая 23:59, у важных дат — учебные
часы) и «Другое время». Единственный текстовый ввод во всём сценарии дат —
`ЧЧ:ММ`, и он подсказан явно.

## Сценарий добавления

`Тип → Предмет → Категория → Название → Описание → Дедлайн → Ссылки →
Подтверждение`. Текстом вводятся только название, описание и ссылки; всё
остальное — кнопками. Пропуск необязательных шагов — кнопкой, без
текстовых токенов. На шаге подтверждения можно сразу задать напоминания.

## Интерфейс

Нижняя reply-клавиатура: Задания, Добавить, Предметы, Группа, Настройки,
Помощь. Её роутер подключён выше FSM-роутеров, поэтому нажатие раздела
всегда прерывает незаконченный ввод.

Список: секция «📝 Задачи», секция «📅 Важные даты», внутри — группировка по
предметам в порядке ближайшего дедлайна. Сквозная нумерация в тексте совпадает
с порядком кнопок. Прошедшие вынесены на отдельный экран.

Команды: в личке `/menu`, `/join <код>`, `/cancel`, `/help`; в групповом чате
`/bind_chat`, `/digest`, `/help`.

## Требования к коду

Без комментариев, docstring на русском у каждой функции, аннотации в
синтаксисе 3.12+, логирование через `logging`, конфиги и структуры — pydantic.
Строковые callback-префиксы не используются: только `CallbackData`-фабрики.
Тексты интерфейса — в `views/texts.py`, экранирование — в `views/common.py`.

## Тесты

`tests/` покрывают: правила напоминаний и планирование (включая DST и границы
дедлайна), календарь, доменные инварианты, репозитории на in-memory SQLite,
менеджеры и сервисы (идемпотентность рассылки, слоты дайджеста), рендер
текста и нарезку под лимит, клавиатуры и сквозные сценарии через настоящий
`Dispatcher` с ботом-заглушкой.
